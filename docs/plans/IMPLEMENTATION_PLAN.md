# 本轮开发计划：交互、放置与波次事件

> 历史实施计划：下文描述 2026-10-15 的问题和设计，功能已落地，源码随后迁入 `core/` 与 `ui/`。当前结构见[架构文档](../architecture/ARCHITECTURE.md)，最新状态见[交接文档](../collaboration/HANDOFF.md)。

日期：2026-10-15。实施者：Codex contributor。产品源码与测试位于根仓库；开始时的未提交修复和构建目录保持原状。

## 目标与已核实的问题

1. 菜单按钮目前只改变鼠标形状，按下时没有视觉反馈；结算页按钮也只有图片。局内没有暂停或退出入口。
2. 点击画面底部 `y=780..799` 会被 60 像素网格吸附到 `y=810`，现有合法性检查没有边界条件，仍建塔并扣金币。玩家也无法在点击前看出候选位置是否可建。
3. 六波出怪硬编码在 `GameWidget`，由多个帧计数器驱动；缺少统一的定时事件容器、外部节奏配置及下一事件预览。保留原有敌人顺序、数量和既有平衡数值，默认总数 90，Boss 位于最终波第 8 个。

## 实施设计

### A. 按钮反馈、暂停与退出

- 菜单、说明页返回和结算页按钮共用“无/悬停/按下”的小状态机。各页面先画原图、再画对应按钮反馈：悬停用白色约 12% 透明度与 2px 浅金描边，按下用黑色约 30% 透明度与 3px 亮金描边，圆角贴合原图按钮；`press` 只记录并立即 `update()`，在同一按钮 `release` 才执行，拖出、释放、失焦和页面切换都清状态。菜单与结果图的早退分支不得盖住反馈。键盘 Esc 仍可关闭说明页。
- 局内保持原 48px HUD `x=20..1180, y=12..60`：状态文字限制在 `x=40..850`，右侧三个 92×32 控件分别为“预览”`(870,20)`、“暂停/继续”`(970,20)`、“退出”`(1070,20)`。全部有悬停、按下反馈；暂停按钮持续高亮。预览按钮展开/收起 `x=840..1170, y=70..215` 的事件面板，面板区域截获点击，不建塔；关闭时不占用地图。状态字幕调整到不与面板重叠的位置。按钮命中优先于选塔/建塔。
- 运行状态显式区分 Running / Paused / Finished。暂停用 `QTimer::stop()`，`updateGame()` 也检查状态；继续只从 Paused 转 Running，重新启动 30ms 计时器。暂停遮罩画在游戏对象之上，HUD/预览面板和可操作按钮画在遮罩之上；暂停时禁用建塔、升级、出售及事件推进。`P`/`Esc` 忽略自动重复键，切换暂停；其它游戏快捷键暂停时无效。
- 暂停同时发 `pauseChanged(bool)` 给 `MainWindow`，对战 BGM 随之暂停/继续；退出和结算切歌仍由现有主窗口流程控制。退出复用 `backToMenuRequested`，由 `MainWindow` 现有回调 `restartGame(false)` 放弃本局、切回菜单与音乐；发信号后立即返回。重开严格按停表、清旧堆/对象、清 UI 状态、完整读配置并排首波、最后按需要启表的顺序，防止旧事件泄漏；菜单停表不能被“继续”误启动。

### B. 防御塔放置

- 保留 60 像素网格和目前的路径安全距离，不变更塔价格、尺寸或伤害。只有原始点击 `y>=60` 且在画面内才进入统一 `BuildEvaluation`；候选中心吸附并夹在完整可见格子 `x=30..1170`、`y=90..750`，再检查当前塔半径完整位于画面/HUD 下方、道路、已有塔和金币。底部点击 `y=780..799` 对应最后一行 `y=750`，不会在画面外扣钱建塔。
- 预览与实际点击共享同一 `BuildEvaluation`。鼠标移动时按当前塔型、金币即时求值，在吸附中心绘制半透明绿/红占地圈；已有塔、HUD 控件/预览面板、暂停、结算时不显示建塔预览且不建塔。避免缓存合法性导致切塔或金币变化后预览与落点不同。路径和背景装饰的禁建规则不扩大到未经定义的美术区域。

### C. 最小堆事件调度与配置

- 新增小型 `AttackScheduler`（QtCore + C++17），使用按 `(dueTick, sequence)` 排序的 `std::priority_queue` 最小堆，统一组织 `Spawn`、`Reinforcement`、`WaveStart` 定时事件。`GameWidget::updateGame` 每 30ms 先推进一个逻辑 tick、在敌人移动/删除前出堆执行到期事件，随后走原攻击/清理/结算顺序。暂停和结算不推进 tick。相同 tick 按入堆 sequence 执行，预览用同一比较器读取。
- `26C-/attack_waves.json` 作为 qrc 内置唯一阵容源，保留六波 90 个敌人、所有类型顺序与唯一 Boss（最终波第 8 个）。其中 Boss 后既有 2 个 virus 和 16 个 ddl 标为 `Reinforcement`，但仍调用相同 `spawnEnemy`、计入总数/已生成数/待生成数与胜利判定，沿用第 4 波强化、路径轮换和 Boss 光环；不额外增加敌人。外部 `applicationDirPath()/attack_rhythm.json` **只能覆盖节奏字段**，不能改阵容。每次开始新局重读，缺失时静默用内置；无效时一次非模态提示并整份回退。先解析到临时对象，全部有效才原子替换；校验精确整数、非负门槛、正时长、合理上限、展开数、唯一 Boss、类型白名单和 64 位 tick 加法。
- 在替换旧实现前，用当前 Qt6 产品源码直接逐 tick 探测并保存 `tests/fixtures/legacy_spawn_trace.txt`：每波相对 tick/敌人类型及切波位置。实际 W6 首怪为 `+9`、末怪 `+243`，因为 W5 最后一组剩余 1 个 burst 计数跨波保留；默认配置通过显式开场节奏复现该可观察轨迹，而新调度本身不泄漏旧状态。旧出怪组被装载的 tick 不立即生成敌人，首怪延迟及组内/跨组间隔由完整轨迹测试锁定。
- 状态机明确为 Spawning → WaitingForClear → WaitingForWaveStart → 下一波 Spawning。最后一个生成事件执行的下一 tick 起、在敌人移动/清理前检查场上数量；第一次 `<=6` 时只入堆一次 WaveStart。如果这次检查在 tick `C`，旧逻辑把它计为 20 次等待中的第 1 次，故 WaveStart 在 `C+19` 执行并发送第 4/最终波提示及音乐信号，当 tick 不立即出怪。若还未达到门槛，预览显示条件而不虚构 ETA；最后一波无下波事件。胜利还要确认 90 个生成型事件全执行、堆中无待生成事件且场上为空。
- 事件面板显示至多 3 个最早事件的类型、波次及剩余时间，增援有显式标签；剩余 tick 用 `max(0,due-current)`，暂停时冻结。预览复制堆读取，不改变真实顺序。外部配置加载失败提示在重开清理之后显示；内置配置损坏则明确报错并阻止空调度进入游戏。

## 验证与交付

- 用连接产品实现的 Qt 6 测试覆盖菜单与胜/败结算按钮：分别发送 press → 重绘/截取按钮区域确认颜色变化 → release，以及拖出取消；验证暂停/继续/退出、停表与重开、暂停禁用塔操作、按钮点击不误建塔。增加少量只读产品状态接口以核对金币、塔数、候选位置等，不单凭像素猜逻辑；放置边界、道路、占用、当前金币和预览与实际落点一致均走真实 `GameWidget`。
- 调度测试逐项核对当前真实产品探针记录的 90 条黄金出怪轨迹、Boss 位置、`Spawn`/`Reinforcement` 标记、同 tick 稳定顺序、`<=6` 门槛和 `C+19` 波切换、外部节奏覆盖及无效回退、重开无旧事件、预览不出堆。覆盖外部文件缺失、打不开、格式/小数/零负/过大/未知字段与内置不可用等分支。以产品实现和保存的旧产品轨迹为证据，不以复制算法作为唯一通过依据。
- 新构建目录使用本机 MSYS2 MinGW64 Qt 6.11.2 配置、编译产品及测试，运行 CTest、必要的离屏 UI 截图检查和 `git diff --check`。更新 `HANDOFF.md` 与 `CHANGELOG.md`；报告实际改动、命令、结果和仍未验证项。不提交或推送。
